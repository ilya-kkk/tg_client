## Страница «Прогрев аккаунтов» — имитация человеческого поведения с режимами интенсивности

Цель: дать пользователю возможность создавать задания прогрева («кампании»), в которых выбранные аккаунты автоматически выполняют действия, имитирующие живого пользователя Telegram — с настраиваемым режимом интенсивности (осторожный / нормальный / агрессивный) и случайными задержками между действиями.

### 1. Модель данных (таблица `warmup_jobs`)

- [x] **Создать таблицу `warmup_jobs` в Supabase** со следующими полями:
  - `id` (uuid, PK, default gen_random_uuid())
  - `user_id` (uuid, FK → users.id, NOT NULL)
  - `name` (text, NOT NULL) — название кампании
  - `account_sessions` (text[], NOT NULL) — список `session_id` участвующих аккаунтов
  - `mode` (text, NOT NULL) — режим прогрева: `'cautious'` | `'normal'` | `'aggressive'`
  - `actions_per_day` (int, NOT NULL) — целевое число действий в сутки (зависит от режима)
  - `enabled_actions` (text[], NOT NULL) — список включённых типов действий (см. §3)
  - `target_channels` (text[], NOT NULL) — список `@username` или `t.me/...` каналов/чатов для чтения и реакций
  - `is_active` (bool, NOT NULL, default false)
  - `created_at` (timestamptz, default now())
  - `updated_at` (timestamptz, default now())
- [x] **Добавить RLS-политики**: пользователь видит и изменяет только свои строки (`user_id = auth.uid()`).
- [x] **Создать индекс** по `user_id` для быстрой выборки кампаний пользователя.

### 2. Конфигурация режимов прогрева

Добавить константы (например, в `app/warmup_config.py`):

| Режим       | `actions_per_day` | Мин. задержка между действиями | Макс. задержка |
|-------------|-------------------|-------------------------------|----------------|
| `cautious`  | 5–15              | 5 мин                         | 30 мин         |
| `normal`    | 20–50             | 1 мин                         | 10 мин         |
| `aggressive`| 60–120            | 15 сек                        | 3 мин          |

- [ ] **Создать файл `app/warmup_config.py`**:
  - `WARMUP_MODES: dict` — словарь с параметрами каждого режима: `min_delay_sec`, `max_delay_sec`, `actions_per_day_range`.
  - `ACTION_TYPES: list[str]` — список всех доступных типов действий:
    - `'read_messages'` — открыть чат и «прочитать» 3–15 последних сообщений (задержка на каждом)
    - `'react_to_message'` — поставить случайную реакцию на случайное сообщение в канале
    - `'join_channel'` — подписаться на один случайный канал из предложенных
    - `'view_story'` — просмотреть истории (Telethon: `GetStoriesRequest`)
    - `'search_global'` — выполнить поиск по случайному слову из словаря
    - `'update_status'` — обновить статус «в сети» (простой connect без действий)

### 3. Backend: Pydantic-схемы и CRUD

### 4. Backend: фоновый воркер прогрева

- [ ] **Добавить планировщик в `app/main.py`** (APScheduler или asyncio-таск):
  - при старте приложения запустить цикл мониторинга активных кампаний;
  - раз в N минут выбирать из Supabase все `warmup_jobs` с `is_active = true`;
  - для каждой кампании запускать воркер (если ещё не запущен).
- [ ] **Реализовать класс `WarmupWorker`** в `app/warmup_worker.py`:
  - хранить состояние: `_running: Dict[str, asyncio.Task]` — активные задачи по `job_id`.
  - `start(job)` — запустить asyncio-таск для кампании.
  - `stop(job_id)` — отменить таск кампании.
  - `stop_all()` — остановить все таски (при shutdown приложения).
- [ ] **Реализовать основной цикл воркера** (`_run_job`):
  - при каждой итерации: случайно выбрать один `session_id` из `account_sessions` и один тип действия из `enabled_actions`;
  - вызвать соответствующий метод (см. §4.1);
  - вычислить случайную задержку в диапазоне `[min_delay_sec, max_delay_sec]` режима, подождать.
- [ ] **Реализовать методы действий** в `app/telegram_client.py` (или `app/warmup_worker.py`):

  #### 4.1 Действия прогрева
  - [x] `warmup_read_messages(session_id, chat)` — открыть диалог, вызвать `GetHistoryRequest`, имитировать задержку «чтения» (0.5–2 сек на каждое сообщение, до 15 сообщений)
  - [x] `warmup_react_to_message(session_id, chat)` — получить последние сообщения, выбрать случайное, отправить случайную реакцию из набора базовых эмодзи
  - [x] `warmup_join_channel(session_id, channel)` — подписаться через `JoinChannelRequest`; если уже подписан — пропустить
  - [x] `warmup_view_story(session_id)` — вызвать `GetStoriesRequest` для случайного контакта или канала из `target_channels`
  - [x] `warmup_search_global(session_id)` — вызвать `SearchGlobalRequest` со случайным словом из встроенного словаря (~50 нейтральных слов)
  - [ ] `warmup_update_status(session_id)` — выполнить `connect()` + `UpdateStatusRequest(offline=False)`, затем через 10–30 сек `UpdateStatusRequest(offline=True)`
- [ ] **Обработка ошибок и FloodWait**:
  - при `FloodWaitError(seconds=N)` — приостановить воркер для данного `session_id` на `N + 60` секунд, залогировать
  - при `UserBannedInChannelError` / `ChatWriteForbiddenError` — пропустить действие, убрать чат из очереди на текущую итерацию
  - при любой другой ошибке — залогировать и продолжить следующую итерацию
- [ ] **Обрабатывать включение/выключение через тумблер** — при `PATCH is_active=false` вызывать `WarmupWorker.stop(job_id)` без перезапуска остальных кампаний.
