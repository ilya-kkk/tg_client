## Страница «Автореакции» — массовая расстановка реакций на новые сообщения в чатах

Цель: дать пользователю возможность создавать именованные задания («кампании»), в каждом из которых несколько аккаунтов автоматически ставят выбранные реакции на новые сообщения в заданных Telegram-чатах с указанной частотой.

### 1. Модель данных (таблица `reaction_jobs`)

- [x] **Создать таблицу `reaction_jobs` в Supabase** со следующими полями:
  - `id` (uuid, PK, default gen_random_uuid())
  - `user_id` (uuid, FK → users.id, NOT NULL)
  - `name` (text, NOT NULL) — название кампании
  - `account_sessions` (text[], NOT NULL) — список `session_id` участвующих аккаунтов
  - `reactions` (text[], NOT NULL) — список эмодзи реакций (до 10)
  - `message_frequency` (text, NOT NULL) — частота: `'every'` | `'1/2'` | `'1/3'` | `'2/3'`
  - `target_chats` (text[], NOT NULL) — список `@username` или `t.me/...` чатов
  - `is_active` (bool, NOT NULL, default false) — тумблер вкл/выкл
  - `created_at` (timestamptz, default now())
  - `updated_at` (timestamptz, default now())
- [x] **Добавить RLS-политики** на таблицу: пользователь видит и изменяет только свои строки (`user_id = auth.uid()` или через переданный `user_id`).
- [x] **Создать индекс** по `user_id` для быстрой выборки кампаний конкретного пользователя.

### 2. Backend: Pydantic-схемы и CRUD

- [x] **Добавить Pydantic-схемы** в `app/models.py`:
  - `ReactionJobCreate` — поля: `name`, `account_sessions: list[str]`, `reactions: list[str]`, `message_frequency: Literal["every","1/2","1/3","2/3"]`, `target_chats: list[str]`
  - `ReactionJobUpdate` — те же поля, все опциональные + опциональный `is_active: bool`
  - `ReactionJobOut` — все поля включая `id`, `user_id`, `is_active`, `created_at`, `updated_at`
- [x] **Добавить эндпоинт `GET /users/{user_id}/reaction-jobs`** — список всех кампаний пользователя, возвращает `list[ReactionJobOut]`
- [x] **Добавить эндпоинт `POST /users/{user_id}/reaction-jobs`** — создание новой кампании, принимает `ReactionJobCreate`, возвращает `ReactionJobOut`
- [x] **Добавить эндпоинт `PATCH /users/{user_id}/reaction-jobs/{job_id}`** — обновление кампании (редактирование или переключение `is_active`), принимает `ReactionJobUpdate`, возвращает `ReactionJobOut`
- [x] **Добавить эндпоинт `DELETE /users/{user_id}/reaction-jobs/{job_id}`** — удаление кампании, возвращает `{ "success": true }`
- [x] **Добавить вспомогательные константы** в `app/telegram_client.py` или отдельный файл:
  - `POPULAR_REACTIONS: list[str]` — 10 самых популярных эмодзи-реакций (👍 👎 ❤️ 🔥 🥰 👏 😁 🤔 💯 🎉)

### 3. Backend: фоновый воркер реакций

- [x] **Добавить фоновый планировщик** (APScheduler или asyncio-таск) в `app/main.py`:
  - при старте приложения запускать цикл мониторинга активных кампаний;
  - выбирать из Supabase все записи `reaction_jobs` где `is_active = true`;
  - для каждой кампании подписываться на новые сообщения в `target_chats` через указанные аккаунты.
- [x] **Реализовать метод `react_to_new_messages`** в `app/telegram_client.py`:
  - подключаться к чату от имени указанного `session_id`;
  - слушать новые сообщения (через Telethon event handler `NewMessage`);
  - применять `message_frequency` для решения, ставить ли реакцию:
    - `'every'` → реагировать на каждое сообщение;
    - `'1/2'` → реагировать на каждое 2-е (random или счётчик);
    - `'1/3'` → реагировать на каждое 3-е;
    - `'2/3'` → реагировать на 2 из каждых 3-х;
  - случайно выбирать одну эмодзи из `reactions` кампании и отправлять реакцию через Telethon;
  - обрабатывать ошибки: `FloodWait`, недоступный чат, отсутствие прав на реакции.
- [x] **Обрабатывать включение/выключение через тумблер** — при `PATCH is_active=false` останавливать слушатели для этой кампании без перезапуска всего воркера.
